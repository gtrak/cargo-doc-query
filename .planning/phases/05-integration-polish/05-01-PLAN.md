# Plan 05-01: Error Handling & Exit Codes

**Objective:** Implement comprehensive error handling with specific exit codes and actionable error messages for production-ready CLI ergonomics.

**Phase:** 05 - Integration & Polish
**Plan Number:** 05-01
**Status:** ✅ Complete (retroactive)

## Context

Phase 5 requires production-ready error handling. Users need clear, actionable error messages and appropriate exit codes for shell scripting integration.

**Key decisions from 05-CONTEXT.md:**
- Use colored output by default (red for errors, yellow for warnings)
- Include `--no-color` flag to disable colors for piping/CI
- Error format: `[ERROR] <message>` with optional context/suggestions
- Warnings go to stderr, never stdout
- Include actionable suggestions (e.g., "Run `cargo doc-query build` first")

## Implementation

### Tasks

#### Task 1: Define Error Types
**Status:** ✅ Complete
**Commit:** Multiple commits

Create comprehensive error enum covering all failure modes:
- `NoCache` - No index found, needs build
- `NotFound(String)` - Type/path not found in index
- `BuildFailed(String)` - Documentation build failure
- `InvalidQuery(String)` - Invalid query syntax/path
- `CacheError(String)` - Cache storage/retrieval error
- `Io(std::io::Error)` - IO operations
- `Json(serde_json::Error)` - JSON parsing errors
- `Config(String)` - Configuration errors
- `Other(anyhow::Error)` - Catch-all

**Verification:** All error types display correctly and return proper exit codes.

---

#### Task 2: Implement Exit Codes
**Status:** ✅ Complete
**Commit:** Multiple commits

Standard exit codes for shell scripting:
- `0` - Success
- `1` - General error
- `2` - No cache found
- `3` - Query returned no results
- `4` - Build failed
- `5` - Invalid query
- `6` - Cache error
- `7` - IO error
- `8` - JSON parsing error
- `9` - Configuration error

**Verification:** Exit codes match documented behavior.
