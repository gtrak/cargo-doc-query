<task type="auto">
  <name>Task 2: Fix rustdoc-json manifest path handling</name>
  <files>src/cli/build.rs</files>
  <action>
    Modify the rustdoc-json invocation in build.rs to use package-local manifest paths instead of workspace manifest.

    The issue (from 01-VERIFICATION.md lines 156-159):
    ```
    Warning: Failed to document anstream: Manifest must be for an actual package. `"./Cargo.toml"` is a virtual manifest
    thread 'main' panicked at src/tools/cargo/src/cargo/core/resolver/features.rs:325:13
    ```

    Current pattern likely uses workspace manifest:
    ```rust
    rustdoc_json::Builder::default()
        .manifest_path("Cargo.toml")  // Wrong - workspace manifest
        .package("anstream@1.0.0")
    ```

    Fix to use package-local manifest:
    ```rust
    rustdoc_json::Builder::default()
        .manifest_path(package_manifest_path)  // Correct - package's own Cargo.toml
        .package(&format!("{}@{}", package_name, package_version))
    ```

    Steps:
    1. Modify `generate_rustdoc_json()` to accept a list of packages with their manifest paths
    2. For each package, use its manifest_path when creating the rustdoc-json Builder
    3. Add panic recovery: wrap the build() call in catch_unwind or add a try_build() wrapper
    4. Log warnings for failed crates but continue with others (graceful degradation per accumulated decisions)
  </action>
  <verify>
    cargo build --quiet && cargo run -- build 2>&1 | head -50
  </verify>
  <done>
    rustdoc-json is invoked with package-local manifests, build completes without virtual manifest errors
  </done>
